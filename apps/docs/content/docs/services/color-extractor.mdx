---
title: Color extractor
description: Wallpaper color histograms for color-ranked discovery
---

Color Extractor reads immutable original wallpaper images and publishes a normalized, alpha-weighted 64-bin HSV histogram. Gateway projects these histograms for the browse page's Color control. Video uploads are intentional no-ops. The service owns no database and never deletes originals.

## Execution and delivery

The extraction capability uses Effect services for histogram extraction and result publication. The image adapter owns S3 reads and Sharp decoding. The native-process decision is recorded in the context ADR `0001-isolate-native-image-decoding`. The event adapter translates legacy and CloudEvents upload messages into local input. Composition owns the clients, consumer, health request fibers and shutdown scope. Pure HSV calculations remain ordinary TypeScript.

The durable consumer `color-extractor-wallpaper-uploaded-consumer` reads `wallpaper.uploaded` from the configured stream. Each replica pulls one message at a time. The existing acknowledgement deadline is 120 seconds, with an in-progress acknowledgement every 30 seconds while processing. The service acknowledges an image only after JetStream confirms the histogram publication, or acknowledges a video after the skip result.

Processing runs at most three times, preserving the previous NATS delivery-count cutoff. Failed attempts now use delayed negative acknowledgements, initially one second then two seconds. Invalid and exhausted messages go to `COLOR_EXTRACTOR_QUARANTINE` on `color-extractor.quarantine`. The quarantine body contains exact original bytes; binary CloudEvents headers identify the original subject, consumer and reason. The service acknowledges the input only after quarantine PubAck.

The broker delivery limit is unlimited so a quarantine outage does not strand input at MaxDeliver. Deliveries after the third attempt retry only the durable quarantine handoff, with delay capped at 30 seconds. Quarantine storage uses discard-new. Operators must monitor pending inputs, quarantine capacity and publication failures. If added quarantine headers exceed the broker's message-size budget, the original remains pending until capacity or the payload budget is repaired. It is not discarded. Replay publishes the stored original body to its original subject; structured input retains its event occurrence identity.

Results use CloudEvents 1.0 on `wallpaper.colors.extracted`, with the unchanged histogram payload. The output ID is derived from the input source and ID; output time is the input occurrence time. The source, ID and NATS message ID stay stable across retries. Broker deduplication is supplementary; replay is safe because extraction reads an immutable original and Gateway treats the result as an idempotent projection. No atomic transaction spans S3 and NATS.

## Resource ownership

S3 reads have a 100-second deadline and health probes have a five-second deadline. Interruption aborts the request and closes its body. The image adapter serializes decoding in an owned child process. A ten-second deadline includes metadata reads and the pixel pipeline. Interruption or deadline kills the decoder and waits for process exit before releasing the permit. This also bounds nonresponsive native metadata work, which Sharp itself cannot cancel. The build emits `decoder.mjs` beside `index.mjs`; deploy both files.

Shutdown stops consumer intake, allows current work to finish within the configured drain period, then interrupts unfinished Effect work before closing clients. Failed startup releases resources already acquired. Health request fibers belong to the HTTP runtime. Telemetry exporters belong to the executable's outer scope.

## HTTP and configuration

`GET /health` reports S3, NATS, consumer and telemetry health. `GET /ready` reports initialized and shutdown state. Non-success responses use RFC 9457 Problem Details; dependency health responses retain their checks and expose the health classification as `healthStatus`. OpenAPI is served at `/documentation`. Development CORS allows localhost and 127.0.0.1 origins.

Configuration retains `PORT`, `NODE_ENV`, `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_BUCKET`, `S3_REGION`, `NATS_URL`, `NATS_STREAM`, `OTEL_EXPORTER_OTLP_ENDPOINT` and `OTEL_SERVICE_NAME`. The default port is 3007, bucket is `wallpapers`, region is `us-east-1`, and stream is `WALLPAPER`. Invalid configuration fails before accepting work.

## Verification

```sh
make check PACKAGE=color-extractor
make test-unit PACKAGE=color-extractor
make test-integration PACKAGE=color-extractor
make run PACKAGE=color-extractor SCRIPT=test:all
make check-crap PACKAGE=color-extractor CRAP_THRESHOLD=30
```

Unit tests cover extraction decisions, the HSV table, real Sharp formats and alpha handling, HTTP translation, configuration, and cancellable S3 sockets. Integration tests cover real SeaweedFS image reads, NATS publication and delivery guarantees, and the production composition processing a stored image. Telemetry tests exercise a real local collector. Linux process tests stop an actual decoder and prove deadline/interruption reaps it. Coverage includes every source file; child-process decoder execution does not contribute to the parent Vitest coverage and remains reported as uncovered despite its blackbox image tests. the shared CRAP tool's callback/generator limitation is tracked in issue #217.

## Rollout

Deploy a Gateway that accepts CloudEvents color results before this worker. The Gateway migration on main already does. Existing retained legacy uploads remain readable, and new Ingestor CloudEvents retain their canonical source and ID. The consumer durable name stays unchanged; startup updates its delivery configuration without resetting its position. Existing broker-exhausted messages may require operator replay and are not automatically recovered by this migration.

Allow the service to create its quarantine stream and update its durable consumer. No database migration is needed. Storage-coordinate payload migration remains deferred; originals retain their current bucket/key interpretation. Stop legacy replicas before relying on durable quarantine guarantees, since mixed old replicas still use their previous termination behavior.
