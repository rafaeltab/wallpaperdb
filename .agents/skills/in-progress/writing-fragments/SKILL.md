<what-to-do>

Run a grilling session to collect writing fragments. Explore possibilities without imposing phases, outlines, or article structure.

Append fragments from either participant, including the initial prompt, to one Markdown file. If no path was supplied, ask once and remember it. Start the file with a single H1 working title, with no metadata, table of contents, or date.

</what-to-do>

<supporting-info>

## What is a fragment

A fragment is text the author might use in the article. It must make sense to the author, but need not define its terms or stand alone for a new reader. It can be a sentence, claim, vignette, code snippet, quote, unfinished thought, or related observations.

Look especially for a **leading word**, a compact term for a recurring idea. When the conversation returns to one idea, push to name it; that term can guide the later structure and title.

## File format

Separate fragments with a horizontal rule (`\n---\n`). Use no body headings, tags, or ordering beyond the order added. A fragment may contain paragraphs, lists, code, or quotes.

## Writing rhythm

Append without asking permission for each fragment. Mention additions briefly without interrupting the interview.

Re-read the file from disk before every write and preserve user edits. Only append unless the user requests a specific edit, deletion, or merge.

</supporting-info>
