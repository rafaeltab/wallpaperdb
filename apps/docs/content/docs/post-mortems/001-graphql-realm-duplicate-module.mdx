---
title: 'PM-001: GraphQL module-identity test failures'
description: Why cold gateway test runs exposed duplicate GraphQL class identities.
---

On 2026-03-30, 26 Gateway GraphQL tests failed after a cleanup and dependency reinstall. This affected the test environment, not production.

```text
Cannot use GraphQLNonNull "WallpaperConnection!" from another module or realm.
```

## Cause and resolution

Vitest loaded GraphQL's ESM entry while Mercurius loaded its CommonJS entry. The two module instances had different constructor identities, so GraphQL's cross-module checks rejected values that otherwise looked identical.

The failure appeared after `make clean` invoked `pnpm store prune` and dependencies were reinstalled. Removing Mercurius's `ssr.noExternal` setting did not resolve it. Pinning GraphQL to one CommonJS file through `resolve.alias` removed the realm failures; one unrelated introspection failure remained.

The alias remains documented beside its implementation in [Gateway's Vitest configuration](https://github.com/rafaeltab/wallpaperdb/blob/main/apps/gateway/vitest.config.ts). Preserve the single module identity when changing dependency resolution or test configuration. A warm transform cache can conceal the problem, so verify cold runs when changing this setup.

Global pnpm store pruning was also removed from routine cleanup. The store is shared across projects; repository cleanup should not alter it as a side effect. The incident does not establish that pruning alone causes duplicate GraphQL modules.

For earlier Mercurius integration context, see the [GraphQL security decision](/docs/architecture/decisions/graphql-security-hardening).
