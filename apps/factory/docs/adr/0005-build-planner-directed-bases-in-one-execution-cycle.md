# Build planner-directed bases in one execution cycle

Accepted direction, with implementation tracked in [issue #735](https://github.com/rafaeltab/wallpaperdb/issues/735). The planner selects a mutually executable batch bounded by available concurrency and remaining admissions, and identifies existing issue code to include in each execution base. An empty inclusion list means freshly fetched `origin/main`. The factory verifies and constructs the requested bases, including automatic joins when necessary, rather than inferring additional issue inclusions. This refines the planning boundary in [ADR 0001](0001-keep-execution-authority-in-the-factory.md) while preserving factory execution authority and the verification policy in [ADR 0003](0003-linearize-verified-unmerged-prerequisites.md).

One execution cycle owns gathering information, planning, base preparation and implementer starts. This prevents competing factory cycles from consuming the same capacity and keeps selected work on a concrete automatic path to implementation. Base construction belongs inside this cycle; an already prepared containing branch is not required before selection. The planner uses current work-in-progress context to choose issues that can proceed together. Future implementation queues and unconditional rejection of backlog overlap were rejected in favor of selecting executable work again in later cycles. Preview remains advisory, and external changes still require freshness checks. Genuinely incompatible requirements remain a separate human-policy decision in [issue #733](https://github.com/rafaeltab/wallpaperdb/issues/733).
