# Replay-safe variant generation with bounded native work

Variant generation uses Effect capabilities and scoped adapter Layers. Generation continues after an individual preset fails, but a batch fails until every selected variant has been stored and its announcement acknowledged by JetStream. Previously the service swallowed publication failures and acknowledged incomplete batches.

S3 and NATS are independent resources. Retrying uses existing deterministic object keys and output occurrence identities derived from the input occurrence and variant. Publication waits for PubAck; an ambiguous publication is safe to retry with the same identity. Stable identities supplement broker deduplication rather than claiming exactly-once delivery. Three failed attempts lead to durable quarantine before acknowledging input; failures to quarantine keep input pending without further generation.

Output uses binary CloudEvents with logical rendition references consumed by Media. The image adapter registers each immutable descriptor before returning a stored variant; failed registration leaves the generation batch incomplete and retryable. Input accepts retained legacy envelopes and Ingestor's structured CloudEvents. Input time supplies stable variant creation and output occurrence times. Object keys, format settings, preset order and nominal dimensions remain compatible. Nominal dimensions describe preset bounds; actual image dimensions can be smaller due to aspect-preserving fit.

Native Sharp work runs in a subprocess because a Promise timeout cannot stop libvips. Interruption kills and reaps the child before releasing the single processing permit. Each source is bounded to 50 MiB, encoded output to 64 MiB, native work to 60 seconds, and one complete variant to 100 seconds. S3 requests and body reads abort on interruption. Deploy the entire dist directory, including encoder.mjs and deferred application chunks. Starting one process per variant adds overhead in exchange for enforceable shutdown and deadline bounds.

New originals use logical references resolved through `ASSET_REFERENCE_BUCKET`. Retained coordinate-based uploads remain accepted and keep their exact original location. See the system asset-descriptor decision in `docs/adr/0006-resolve-immutable-assets-through-storage-descriptors.md`. Generated variants remain owned by this context; neither this migration nor its cleanup deletes source or generated objects. Variant writes are conditional creates: the first stored rendition wins, including when replicas use different encoding settings. Conflicting writers read its authoritative size, MIME and stored creation time; they never overwrite it. New objects store a fingerprint of the original bucket/key alongside the creation time; a different source or malformed/partial metadata fails closed. Legacy objects with neither owned field are adopted read-only if their size and MIME are valid, retaining the input timestamp fallback. Legacy adoption relies on the existing immutable wallpaper identity and producer-owned key namespace because old objects have no source fingerprint. Encoding settings affect new targets only; deliberate regeneration of existing keys requires a future versioned target identity policy.

Quarantine retains file-backed records for 30 days with a 1 GiB capacity and DiscardNew overflow. Expiration is the explicit repair horizon; operators must repair or export records before it expires. Startup validates existing stream guarantees and fails on incompatible configuration rather than silently changing retained history. Operators must inspect/export history and deliberately migrate any incompatible stream. Smaller capacities are accepted; per-subject limits require DiscardNewPerSubject to prevent eviction of prior chunks.

A fitting quarantine record retains the exact original body. Oversized records use bounded chunks followed by a manifest containing quarantineId, chunkCount, chunkSize, totalBytes, sha256 and stream sequences. To replay, read those sequences in order, concatenate their bodies, and verify the byte count and SHA-256 before republishing the original bytes. Original acknowledgement requires every chunk and the manifest to receive PubAck. Full capacity or an envelope too small to fit leaves the original pending until an operator restores capacity. The manifest is the completion record; orphaned partial chunks do not establish completed handoff.
