---
title: Profile picture delivery
description: The original origin-authorization decision and its replacement.
---

The [original decision](https://github.com/rafaeltab/wallpaperdb/blob/main/docs/adr/0004-authorize-profile-picture-delivery-at-origin.md) required Asset to check User's current-picture authority on every origin request. An asynchronous projection alone could expose a replaced picture while events were delayed. The uncached, fail-closed check prevented that exposure but made delivery depend on User availability.

[ADR 0011](https://github.com/rafaeltab/wallpaperdb/blob/main/docs/adr/0011-unlink-profile-pictures-before-asynchronous-media-deletion.md) and [ADR 0012](https://github.com/rafaeltab/wallpaperdb/blob/main/docs/adr/0012-own-stable-assets-and-immutable-sources-in-media.md) supersede that design for the target architecture. Profile unlink precedes asynchronous Asset deletion, so an already-known URL may remain usable until deletion is processed. Asset owns source bytes and private retention.

Neither origin retirement nor deletion can recall copies already downloaded or cached. The target retains the 30-day private-evidence default and recorded expiry dates without choosing a new cache policy.
