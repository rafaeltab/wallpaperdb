## Planned comparisons

1. **Precomputed family amounts + native numeric scoring:** all eligible documents participate; indexed range filters can narrow explicit constraints. Simple consistent global objective, but functions may still evaluate every match.
2. **Precomputed family amount tokens + native Boolean scores:** the same quantized amount objective, with postings and competitive-score pruning available to the engine. Restricted indexed range catalog; measure actual global ordering and execution behavior.
3. **Dynamic range scoring inside OpenSearch:** retain arbitrary region controls and joint-overlap semantics for one/two regions, with an exhaustive scoring baseline. Globally correct for the stored descriptor, but likely more costly and still subject to palette error.
4. **Safe global bounds for fine amount scoring:** use any K valid seed results to establish an upper bound T on the Kth total absolute amount error. Every better or tied document must satisfy each indexed per-family error ≤T. Search that necessary-bound set globally with the fine scorer. This is exact pruning for the declared additive objective, not reranking a capped candidate set. Seed and final queries use the same PIT; pagination must widen the bound when its complete prefix is exhausted.
5. **Indexed pair unions for joint matching:** store source-pixel coverage for each family and the union of every pair. One/two-family requests need only one/three numeric values per document. A closed form preserves the distinct-area transport semantics, including overlapping families, without palette clustering loss. Compare an exhaustive global query and a safely bounded version. This prototype has hard boundaries and no joint center-quality secondary objective yet.

Native family methods use marginal amounts, which can overlap. This is a different declared semantic model from distinct portions in the joint transport scorer. Compare that product tradeoff instead of disguising it as an equivalent algorithm.
