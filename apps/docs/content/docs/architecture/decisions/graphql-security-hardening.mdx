Accepted on 2024-12-21. The original IP-plus-User-Agent quota has been superseded by [Gateway ADR 0003](https://github.com/rafaeltab/wallpaperdb/blob/main/apps/gateway/docs/adr/0003-weighted-ip-admission-with-bounded-fallback.md). Use the [gateway admission contract](/docs/guides/gateway-admission) for current limits, client responses, telemetry, and deployment requirements.

## Context

Gateway needed bounds on query depth, complexity, breadth, pagination, and batches, plus cursor validation and production introspection restrictions. At the time it used Fastify 5.2.0, Mercurius 16.6.0, and GraphQL 16.12.0.

The initial plan used `graphql-depth-limit`, `graphql-query-complexity`, and Mercurius's `validationRules`. Validation caching and JIT execution meant those rules did not provide per-request inspection. The complexity library also caused duplicate GraphQL module-identity errors, and its estimators returned zero in the attempted integration.

## Decision

Use Mercurius's built-in depth limit and a custom complexity calculator in `preExecution`, which runs for each execution. Keep transport checks in Fastify and cursor validation in resolvers.

The original layers were:

- Fastify `preHandler` enforced Redis-backed IP-plus-User-Agent request quotas and a ten-query batch limit.
- Mercurius enforced depth five and disabled production introspection through `NoSchemaIntrospectionCustomRule`.
- `preExecution` calculated schema-specific costs and bounded unique fields and aliases.
- Resolvers checked HMAC-signed cursor payloads containing an offset and timestamp, with a default seven-day expiry.

These values describe the original decision. Current configuration lives in [Gateway's config](https://github.com/rafaeltab/wallpaperdb/blob/main/apps/gateway/src/config.ts).

## Rationale and alternatives

Custom inspection avoided the failed library integration and allowed schema-specific field costs and pagination multipliers. It also made the team responsible for maintaining those costs as the schema changed. Breadth inspection distinguished unique fields from repeated occurrences and bounded aliases separately.

Disabling JIT would give up its execution optimization. Replacing Mercurius with Apollo Server required a framework rewrite for this integration problem. Neither was chosen.

The historical User-Agent quota tried to distinguish people behind shared IPs, but a caller can change User-Agent. The replacement quota uses trusted IP identity and explicitly accepts shared-network budgets.

Signed, expiring cursors replaced unsigned base64 offsets so clients could not alter an offset without invalidating its signature. Signing does not encrypt the payload.

Production errors hid diagnostic values while retaining stable error codes; development errors exposed the measured value and limit. OpenTelemetry recorded query scores and rejection reasons. The original IP-labelled rate-limit metrics and broad denial-of-service guarantees are obsolete; use the current admission contract.
