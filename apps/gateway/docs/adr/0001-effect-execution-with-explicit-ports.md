# Effect execution with explicit application ports

The gateway adopts Effect 3 for composable execution, typed outcomes, tracing, controlled clocks, and scoped resource release while retaining Fastify, Mercurius, OpenSearch, Redis, and NATS as adapters. Application ports remain constructor-injected TypeScript interfaces with colocated namespaced `Symbol.for` tokens; factories hide their implementing classes, and expected failures are discriminated outcomes carried by Effects. This keeps the coding standards intact and permits evaluating Effect without rewriting the gateway's public protocols or introducing a second dependency container.

The gateway is one application hexagon in the Gateway Catalogue context. Catalogue reads, projection updates, request admission, and availability use language-only DDD; no entity/aggregate machinery is needed. Composition alone selects adapters and resource lifetimes. The OpenTelemetry bridge is pinned to the release compatible with the repository's OpenTelemetry 1.x SDK.

## Consequences

- Effects run at HTTP and broker boundaries. Capabilities neither run their own runtimes nor inspect transport or vendor errors.
- OpenSearch owns atomic projection updates. Replayed variants do not duplicate renditions, uploads preserve enrichment, and enrichment arriving before an upload stays hidden until publication.
- Versioned Profile snapshots advance monotonically. Legacy wallpaper producers have no entity version; complete color snapshots and rendition replacements use occurrence time and identity for deterministic convergence, without claiming producer ordering.
- Existing indices receive additive projection metadata mappings without deleting their contents. A retained variant's creation time prevents an older rendition from replacing it before occurrence metadata has been established. Existing color snapshots contain no extraction time or event identity: the shared `updatedAt` can reflect an unrelated variant update and cannot safely supply a color version. The first color event after upgrade establishes that metadata; an older retained color event may temporarily replace a legacy snapshot until the latest extraction is replayed. Deployments requiring preserved historical color ordering must replay the complete retained color history before reopening catalogue traffic; this migration does not claim to reconstruct missing historical event identities.
- The broker accepts CloudEvents 1.0 and translates the existing producers' legacy envelopes at intake. Replacing the contracts and retained event history of the other applications remains a separate cross-application migration. The gateway emits CloudEvents quarantine records with stable identity and acknowledges only after confirmed projection completion or confirmed quarantine publication.
- Transient projection retries are finite and delayed. If quarantine itself is unavailable, delivery remains unacknowledged and quarantine is retried until durable acceptance is possible.
- Redis failure falls back to an instance-local window. This preserves availability but the fallback limit is per replica; it does not claim a distributed quota during a Redis outage.
