# Use reported PR merges as WDB landing evidence

Accepted for the WDB factory rewrite in the resolution of [Define the factory library and WallpaperDB consumer responsibilities](https://github.com/rafaeltab/wallpaperdb/issues/806#issuecomment-7013886515). WDB considers an associated PR reported as merged by GitHub to be landed, without requiring its individual target to be the default branch or independently verifying its merge result in default-branch history. This keeps landing recognition independent of commit ancestry and merge strategy while accommodating [GitHub stack merges](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/merging-stacked-pull-requests), which can deliver several PRs together.

Branch-only integration merges are outside WDB's supported workflow. If a PR is merged into another feature branch and that branch is later abandoned, WDB may already have considered the Project item landed even though its code never reached the default branch. The maintainer explicitly accepts this limitation instead of requiring ancestry verification. The reusable library exposes source-control observations; this interpretation belongs to WDB.

For the rewrite only, this replaces the verified-landing requirement in [ADR 0001](0001-keep-execution-authority-in-the-factory.md) and landing-containment verification in [ADR 0003](0003-linearize-verified-unmerged-prerequisites.md) and [ADR 0009](0009-verify-main-rebases-and-review-reconstructed-heads.md). It does not replace their other verification rules or change the current implementation. Whether an associated PR fully implements its issue, automatic issue closure, and removal from the Project canvas remain separate decisions.
