# Weighted IP admission with bounded fallback

Gateway protects ordinary discovery fairness with a weighted budget per trusted client IP, and bounds each replica's active GraphQL work independently. Redis shares the budget across replicas while available. On dependency failure, a smaller local budget preserves limited discovery availability. This replaces the admission bypass and `admission.quota.unenforced` policy in [ADR 0002](0002-effect-services-and-owned-lifetimes.md), and the IP plus User-Agent identity in the historical GraphQL security decision.

Cost is the selected operation's existing query-complexity score with resolved variables. Inspection rejections cost 100 points. Charging happens before backend execution, and admitted work keeps its charge after failure, timeout, or disconnect. Request-count quotas would treat materially different queries alike. User-Agent identity lets callers reset their allowance, so authentication and User-Agent do not change the IP budget. Broad initial budgets accommodate shared networks without promising fairness between people behind the same address.

Healthy Redis provides an atomic, continuously refilling shared bucket. Default capacity is 1,000,000 points, refilled over a minute. The local fallback has 100,000 points per IP per replica over a minute. Outage traffic can consume one local budget on every replica, and a process restart clears its local budgets. On recovery, new admissions immediately return to Redis without merging local charges. An ambiguous failed Redis reservation may already have consumed shared points; retrying it could double-charge, so the gateway does not replay it. These choices favor bounded availability over a fleet-wide quota during dependency failure.

Occupied quota-command capacity, a full local budget store, and occupied active-work capacity reject with HTTP 503 instead of bypassing enforcement or adding a queue. A request deadline and disconnect cancellation interrupt work; a request retains its active slot until cancellation cleanup settles. HTTP 429 identifies an exhausted cost budget. Existing depth, breadth, pagination, and complexity limits remain independent controls. [Load evidence](../admission-load-test.md) explains the starting limits and their measurement boundaries.

The production ingress must bound raw request rates and request body sizes, establish trusted client-IP forwarding, and prevent direct public access to replicas. Production startup requires explicit trusted proxy addresses and enabled distributed admission. These checks cannot verify network isolation. No ingress product is selected; local Caddy is a development aid. The [operational contract](../../../docs/content/docs/guides/gateway-admission.mdx) defines deployment verification.

The threat model includes ordinary bursts, expensive queries, and dependency failures. Source-IP rotation and distributed attacks are outside the per-IP quota guarantee. Shared-IP contention and proxy misconfiguration also lie outside that guarantee. Active-work limits bound gateway concurrency, not all ingress bytes, connection state, CPU time, or downstream work after a cancellation reaches a remote server. This is not comprehensive denial-of-service protection.

Aggregate cost, denials, saturation, fallback, and recovery telemetry has bounded attributes and exports no raw or pseudonymous IP labels. Healthy Redis also supplies an approximate mean of charged points per active IP for the current minute. The mean is unavailable during outages or invalid telemetry, excludes local charges, and is not a per-IP percentile. Operators must investigate loss of the shared guarantee even when requests still succeed.
