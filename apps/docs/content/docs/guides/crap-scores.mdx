title: Local CRAP scores
description: Use complexity and coverage to find functions worth investigating.
---

CRAP combines cyclomatic complexity with test coverage to identify candidates for tests or refactoring. It does not measure developer performance or prove correctness.

```sh
make crap
make check-crap CRAP_THRESHOLD=30
```

Both commands build dependencies and run unit and integration coverage, requiring Docker. Add `PACKAGE=<workspace>` to limit the default repository-wide scope. Run one CRAP command at a time, without other tests writing the same coverage directories.

`make crap` sorts functions by descending score. `make check-crap` prints functions above the threshold and fails if any exceed it; equality passes. The example threshold is not repository policy or a CI gate. Failed tests or invalid reports fail the command instead of reusing stale coverage.

## Interpret the report

```text
CRAP = complexity² × (1 − coverage)³ + complexity
```

Coverage is a fraction from zero to one, using the lower applicable statement or branch coverage. Branchless functions use statement coverage; missing measurements count as zero. Complexity 4 with 50% coverage scores 6; without coverage it scores 20. E2E coverage does not contribute, so inspect the tests before treating a high score as missing coverage.

Callbacks, nested functions, generators, and curried wrappers such as `Effect.fn` receive separate scores. Nested decisions belong to the nested function; source positions distinguish anonymous callbacks. Calling a wrapper or constructing an Effect does not cover its callback body.

The shared Vitest 3 configuration enables AST-aware coverage remapping; Vitest 5 already uses it. Legacy V8 reports may omit callback metadata or contain only function-entry branch counters. If those records cannot establish a function's own statement or source-branch coverage, the analyzer uses zero.

V8 can mark a generator's first yield covered at iterator creation, before `.next()` runs, overstating coverage for short generators. The [provider fixture](https://github.com/rafaeltab/wallpaperdb/blob/main/test/fixtures/crap/callbacks.test.ts) checks creation separately from execution.

## Maintenance

The private `@wallpaperdb/crap-typescript-core` workspace records its [upstream provenance and Apache-2.0 license](https://github.com/rafaeltab/wallpaperdb/blob/main/packages/crap-typescript-core/UPSTREAM.md). [Issue #239](https://github.com/rafaeltab/wallpaperdb/issues/239) tracks a possible upstream contribution.

Use `make test-unit PACKAGE=crap-typescript-core` and `make check-types PACKAGE=crap-typescript-core` for analyzer changes. The root [provider integration tests](https://github.com/rafaeltab/wallpaperdb/blob/main/test/integration/crap-provider.test.ts) exercise installed Vitest 3 and 5 coverage and supported legacy reports. Run `make test-integration PACKAGE=root` and `make check-types PACKAGE=root` for those changes. These checks also run in CI.

[crap.config.mts](https://github.com/rafaeltab/wallpaperdb/blob/main/crap.config.mts) owns scope and exclusions; [scripts/crap.mts](https://github.com/rafaeltab/wallpaperdb/blob/main/scripts/crap.mts) owns orchestration. If a killed process leaves `coverage/.crap-lock`, confirm it is no longer running before removing the lock.
