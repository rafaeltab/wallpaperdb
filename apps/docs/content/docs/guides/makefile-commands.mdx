Run `make` or `make help` to see every command. Help is generated from the target descriptions in the Makefile.

## Everyday workflow

```bash
make install             # Install dependencies and initialize worktree configuration
make infra-start         # Start this worktree's infrastructure
make dev                 # Watch all application containers
make test-unit           # Fast tests
make check               # Build, lint, and type-check
make ci                  # Full validation, including container tests
```

## Select a workspace

Use `PACKAGE` with a directory name under `apps/` or `packages/`, without the `@wallpaperdb/` prefix. Omitting it runs the task across workspaces that implement it. Turbo still builds dependencies when the task requires them.

```bash
make build PACKAGE=web
make test PACKAGE=ingestor
make test-integration PACKAGE=ingestor
make test-e2e PACKAGE=web-e2e
make check-types PACKAGE=react-muuri
make lint PACKAGE=gateway
make format PACKAGE=media
make dev PACKAGE=docs
make migrate PACKAGE=user
```

`build`, `test`, `test-unit`, `test-integration`, `test-e2e`, `format`, `lint`, `lint-fix`, `check-types`, `check`, `dev`, and `migrate` accept `PACKAGE`. Unknown workspace names fail before a command runs. A workspace must implement the requested task; for example, the ingestor has integration tests, while the web frontend has unit tests.

`make dev` watches the entire Compose application stack. With `PACKAGE`, it runs that workspace's development script: application services watch their Compose container, while docs starts its local development server. Start infrastructure first for application services.

`make test` runs each workspace's `test` script. Use the explicit test tiers to select unit, integration, or E2E coverage; `make ci` runs all three. Integration and E2E targets limit Turbo concurrency to one and require Docker.

Use `FORCE=1` to bypass Turbo's cache, for example `make build PACKAGE=web FORCE=1` or `make ci FORCE=1`. CI always checks the entire repository, regardless of `PACKAGE`.

## Less frequent package scripts

Use `run` for scripts that don't need their own shared target. Both `PACKAGE` and `SCRIPT` are required. `ARGS` passes arguments to the script. This runs the package script directly, without Turbo's dependency builds or cache; build dependencies first when needed.

```bash
make run PACKAGE=web SCRIPT=preview
make run PACKAGE=web SCRIPT=test:watch
make run PACKAGE=ingestor SCRIPT=test ARGS='test/upload.test.ts'
make run PACKAGE=react-muuri SCRIPT=storybook
make run PACKAGE=react-muuri SCRIPT=build-storybook
make run PACKAGE=ingestor SCRIPT=db:studio
make run PACKAGE=ingestor SCRIPT=gen:swagger
make run PACKAGE=docs SCRIPT=gen:swagger-pages
make run PACKAGE=web-e2e SCRIPT=test:e2e:ui
make run PACKAGE=ingestor-e2e SCRIPT=verify-no-imports
```

Available scripts are listed in each workspace's `package.json`.

## Containers and databases

Infrastructure commands retain the worktree's project name and ports from `.worktree`.

```bash
make infra-start
make infra-logs
make infra-stop
make infra-reset         # Asks for confirmation before deleting this worktree's data

make apps-start          # Build and start all app containers
make apps-start SERVICE=ingestor
make apps-build SERVICE=ingestor
make apps-logs SERVICE=ingestor
make apps-stop SERVICE=ingestor  # Stop only this container
make apps-stop           # Tear down the application stack

make psql                # Default database
make psql DB=ingestor    # wallpaperdb_ingestor
make migrate             # Apply all workspace migrations
```

`SERVICE` is a service name in `infra/docker-compose.apps.yml`. These commands use the development images and app-level environment files from that Compose configuration. They replace the old standalone per-service Docker recipes. For a production image, use the service's `build:docker` script, for example `make run PACKAGE=ingestor SCRIPT=build:docker`.

Redis and NATS inspection commands remain available in `make help`. `redis-flush` deletes all Redis data without confirmation.

## Repository maintenance

`make help` lists storage verification, coverage reports, CRAP score checks, Sandcastle credentials and tests, worktree teardown, and cleanup. `make test-make` checks command routing without starting services; it also runs in CI.

`make clean` removes installed dependencies, build output, caches, generated OpenAPI specs, and coverage. `make worktree-remove` tears down this worktree's containers and releases its slot.

## Migrating old commands

Per-workspace aliases have been removed. Use these replacements:

| Old command | Replacement |
| --- | --- |
| `make web-build` | `make build PACKAGE=web` |
| `make ingestor-test` | `make test PACKAGE=ingestor` |
| `make web-check` | `make check-types PACKAGE=web` |
| `make docs-dev` | `make dev PACKAGE=docs` |
| `make web-test-watch` | `make run PACKAGE=web SCRIPT=test:watch` |
| `make web-e2e-test` | `make test-e2e PACKAGE=web-e2e` |
| `make ingestor-docker-run` | `make apps-start SERVICE=ingestor` (development Compose container) |
| `make psql-media` | `make psql DB=media` |
| `make db-studio-media` | `make run PACKAGE=media SCRIPT=db:studio` |
| `make ci-force` | `make ci FORCE=1` |
| `make check-types-force` | `make check-types FORCE=1` |

When adding a workspace, define its scripts in `package.json` and use the shared commands. Add a Make target only for a new repository-wide workflow.
