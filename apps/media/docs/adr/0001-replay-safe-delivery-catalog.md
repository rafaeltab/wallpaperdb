# Replay-safe delivery catalog

Media uses application-owned Effect ports for delivery and atomic catalog acceptance. PostgreSQL commits occurrence acceptance, catalog state, target acceptance, and availability publication intent in one transaction. The outbox publishes with stable CloudEvent and NATS message identities, then records completion after PubAck. PostgreSQL and JetStream are independent resources; an ambiguous publish may repeat the same occurrence.

The catalog is immutable for wallpaper targets. A later occurrence cannot overwrite an original or an existing variant. Variants can precede their parents, so their rows do not require a parent foreign key; the publisher waits until the parent exists. Profile heads advance by producer version, while late picture metadata remains useful. Picture origin authorization retains the exception in `docs/adr/0004-authorize-profile-picture-delivery-at-origin.md`.

Legacy rows predate the occurrence and target ledgers. Their first reconciliation preserves stored metadata and reuses existing variant identity. It may issue one new stable availability announcement because the old implementation did not retain publication evidence. Existing duplicate legacy rows remain intact; deterministic selection avoids destructive cleanup. Non-image originals remain deliverable, but the image-only availability contract cannot announce them.

## Lifetimes and recovery

One scoped application graph owns PostgreSQL, S3, NATS, consumers, the outbox worker, and native resize workers. HTTP stops accepting work and allows five seconds for existing requests before closing their sockets. Broker workers stop pulling, allow bounded completion, then interrupt. Every database operation owns a checked-out connection. Interruption destroys that connection; PostgreSQL rolls back any open transaction. A fifteen-second total operation deadline also closes it. Connection acquisition is bounded at five seconds, and statement and idle-transaction limits are ten seconds. The Linux PostgreSQL deployment uses `client_connection_check_interval=100` so a disconnected backend notices the closed socket during blocked work; the lock-contention integration tests verify release. If a COMMIT response was lost, the transaction outcome remains ambiguous and the occurrence/target ledgers resolve replay. See [PostgreSQL connection checks](https://www.postgresql.org/docs/16/runtime-config-connection.html).

S3 reads have a thirty-second deadline covering acquisition and streaming and admit at most 128 simultaneous reads. Native image work runs in at most four child processes with thirty-second deadlines. Closing a response releases its byte source; cancelled native work is killed and reaped before its slot can be reused. Input images remain limited to 268402689 pixels. Default output bounds are 7680 by 4320, with the same bounds applied to inferred dimensions. Profile bodies are fully read under a byte limit before immutable caching is enabled.

Resize requests inspect the immutable original bytes to establish displayed dimensions before admission, upscale avoidance and source matching. This covers existing orientation-bearing originals whose catalog dimensions describe raw pixels. Catalog rows and original objects retain their stored meaning and bytes. Geometry inspection consumes its read, shares the native encoding pool and deadlines, and returns only a bounded dimension/orientation frame. Delivery acquires a fresh read after inspection. Unchanged original delivery requires no image inspection; requests matching the inspected displayed original size retain the original-delivery exemption from resize limits.

Historical variants do not record whether EXIF was applied before stripping metadata. For an original requiring an EXIF transform, Media therefore transforms the original rather than reusing an unverifiable variant. For other originals, Media retains catalog selection but inspects the selected variant's actual geometry before exact matching or transformation. A variant with an orientation transform or an inferred output beyond the limits falls back to the already inspected original. This trades additional read/inspection work for safe admission without rewriting immutable catalog facts, reprocessing historical variants, or changing ingestion contracts. A resize cannot establish source geometry if the original is missing or unreadable and fails closed through the existing absence or technical-failure outcomes.

Consumers use three processing attempts with delayed retries. Invalid or exhausted inputs must receive durable quarantine acceptance before acknowledgement. Broker redelivery itself is unlimited so an unavailable quarantine does not strand work at MaxDeliver. `MEDIA_QUARANTINE` is file-backed, uses limits retention, expires at thirty days, and rejects new writes at one GiB. Failed quarantine writes leave the input pending. Large records use acknowledged chunks and a final manifest. Ordinary records retain binary CloudEvent headers under `original-ce-*`; when copied headers cannot fit, an `original-message-v1` frame archives the original headers and bytes inside the chunks. Existing formats and occurrence identities remain valid. Use the [shared quarantine replay procedure](../../../../apps/docs/content/docs/guides/service-upgrades.mdx#quarantine-replay) to validate and decode either format while preserving the original source and ID.

Media does not delete source objects. Ingestor, Variant Generator, and User retain their existing object lifecycle responsibilities. Media's storage credentials must be read-only for their private buckets; quarantine access is restricted to operators because it retains original event bytes.
