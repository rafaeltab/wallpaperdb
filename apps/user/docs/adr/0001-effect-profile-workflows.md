# Own Profile transitions and picture recovery through Effect capabilities

User owns Profile decisions, Handle claims, picture adoption, and the corresponding public events. Its `Profiles`, `Pictures`, `Maintenance`, and `Availability` capabilities use application-owned Effect ports and Layers. This keeps authorization and domain decisions independent of Fastify, Clerk, Drizzle, NATS, and object storage while giving the process one resource lifetime.

A Profile command carries the authenticated principal. Its target Profile ID comes from that principal; a command cannot supply a second owner. Initial picture adoption uses a separate import-lease operation, which cannot override a later manual upload or removal. Domain rejection and intentional no-op are values. Infrastructure failures use tagged errors, and programmer defects and interruption retain their distinct behavior.

Profile writes use one scoped transactional port. The PostgreSQL adapter locks the owner and relevant picture records, then supplies a local snapshot to a pure application decision. The snapshot's observation time is captured after acquiring those locks so an expired staged picture cannot be adopted using an earlier request timestamp. The adapter commits accepted Profile state, claims, asset transitions, and the complete outbox event together. Drizzle transactions and event wire schemas stay in the adapter. The public Profile version and claim generation retain their existing meanings.

Picture storage and PostgreSQL cannot share a transaction. A durable `uploading` candidate precedes the immutable object PUT; a bounded upload lease prevents concurrent cleanup, and successful completion makes the candidate `staged`. Adoption and deletion use the same owner-before-asset lock order. Cleanup marks an eligible, unreferenced asset `deleting` before external DELETE, and retains its tracking row until deletion succeeds. A crash or ambiguous storage response leaves recoverable evidence. Active pictures remain available only while both the asset and authoritative Profile reference agree.

The captured Clerk source URL is private job data. It never belongs in public events, Profile responses, or failure diagnostics. Imports stop after twelve claimed attempts or a permanent rejection, clear the URL, and complete with the generated avatar when no picture was adopted. Manual changes also clear and fence the job. Retrying an immutable object PUT does not overwrite a previously written object. Staged or retired deadlines remain the deadlines recorded when those states were created.

Outbox publication is at least once. An acknowledged publish is followed by a separate completion write, so an ambiguous acknowledgement or a crash between those steps can republish the same occurrence. The publisher preserves the recorded event ID, source, payload, and originating trace metadata; downstream projection versions and claim generations remain necessary. Broker deduplication alone is not an exactly-once guarantee. Wallpaper ownership accepts the first stored owner under duplicate or conflicting input. Poisoned or repeatedly failing deliveries require durable quarantine before source acknowledgement, and full quarantine storage applies backpressure.

Scoped Layers own database connections, broker consumption, workers, storage clients, and telemetry integration. Shutdown stops admission, gives active work a bounded opportunity to finish, then interrupts it before closing dependencies. Database interruption terminates its leased PostgreSQL backend through a separate bounded cancellation connection and destroys the client socket. Image encoding runs in a killable child process. HTTP clients and storage requests receive abort signals and deadlines. Database diagnostics retain SQLSTATE without query values, which can contain private URLs or authored text.

Explicit Effect spans trace the identity, picture-source and persistence boundaries with safe diagnostics. Automatic Undici and PostgreSQL instrumentation is disabled because it records private source URLs or raw database error text before adapter sanitization. Fresh-process exporter tests exercise both leak paths with telemetry initialized before application imports.

The scoped dependency monitor probes database, broker and worker health every thirty seconds and emits a timestamp for stale-signal alerts. On-demand identity, picture-source and object-storage signals retain the outcome of the last operation. A technical failure remains visible through idle periods and retry backoff until another operation succeeds. Intentionally disabled telemetry is optional; deployments with no telemetry must also disable the missing-signal alert.

## Rollout and compatibility

Apply the picture-state and outbox-tracing migrations before starting the new service. Drain and stop old User replicas first: old cleanup code does not recognize `uploading` or `deleting`, so mixed workers would not honor the new recovery protocol. The additive enum values make rollback a state-reconciliation exercise; do not simply restart an older image against unresolved new-state assets. Existing recorded deadlines, Profile IDs, Profile versions, Handle claims, and event payloads are preserved.

Existing Profile commands retain their validation, concurrency, cooldown, alias, and Biography contracts. Problem type URIs now use the repository's documented `docs/problems/<type>.md` namespace. Initial Handle allocation also corrects a boundary bug: trimming a trailing hyphen after truncation must not produce a Handle below the configured minimum. The normalized stem is padded to that minimum.

Media still checks current picture availability at the User origin before delivery. Removal cannot recall copies already cached by a browser or CDN, and local evidence cleanup does not erase downstream projections or the retained NATS history. These limits follow the existing system decisions on Profile identity, Biography policy, and picture delivery.
