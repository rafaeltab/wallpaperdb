# Reconcile completion from versioned agent state

Delayed notifications can follow a successful agent response, and legitimate publication changes can replace the reviewed starting commit. Following the maintainer decision in [issue #757](https://github.com/rafaeltab/wallpaperdb/issues/757), completion uses the latest coherent versioned state after the actual stage instruction, once supported T3 observations establish inactivity throughout the owning lineage. Local checks, applicable independent reviews, clean owning Git state and authoritative publication identity must agree at the final head. The starting publication commit does not constrain a freshly checked and reviewed final head.

An idle inconsistency authorizes bounded reconciliation in the existing agent and intended PR. The durable per-job budget survives stage transitions and restarts; exhausted attempts require maintainer intervention and explicit reset to restore automatic reconciliation. Agents choose authorized PR changes and may preserve unrelated commits separately. The factory does not clean Git or blindly publish local HEAD. Hosted CI remains an independent readiness gate.

The versioned [response contract](../../src/capabilities/job/contract.ts) and one-time migration replace the legacy-success acceptance clauses of [ADR 0006](0006-order-completion-by-logical-delivery.md) and [ADR 0007](0007-retain-relative-provider-run-order.md). Their logical-delivery and relative-ordering decisions remain in force. Existing claims and audit history remain intact, preserving the [uncertain-effect safeguards](0002-preserve-claims-across-uncertain-external-outcomes.md). Failed migration requires intervention rather than a compatibility parser or repeated migration instructions. See the [completion rules](../../README.md#completion-and-ordering) and [upgrade procedures](../../OPERATIONS.md#upgrade-and-recovery).
