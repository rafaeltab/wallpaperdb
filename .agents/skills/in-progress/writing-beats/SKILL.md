<what-to-do>

Shape the user's Markdown raw material into an article one beat at a time. Exploration is finished; choose a path through the supplied material. Ask once for the article's save path if none was supplied.

1. Settle with the user which concepts the audience already knows. See [Grounding](#grounding).
2. Offer 2–3 starting beats with different entry points. Each must use only grounded concepts; state which new concepts it introduces and which later beats it enables. Show the candidates before writing, and let the user pick.
3. Write only the selected beat to the article file.
4. Re-read the article, then offer 2–3 reachable next beats and state what each introduces.
5. Repeat until the journey reaches a natural end.

</what-to-do>

<supporting-info>

## Grounding

A **grounded** concept is one the audience already knew or an earlier beat introduced. Track these concepts as the article grows. A beat may rely only on grounded concepts; when a concept has a name, introduce the idea and its term together. This applies to ideas as well as jargon.

If a candidate requires an unintroduced concept, add a grounding beat first or revisit audience prerequisites with the user. Balance the prerequisites against readers' knowledge without filling the opening with definitions.

## What is a beat

A beat makes one move, such as setting a scene, making a point, or asking a question. It may be a sentence or several paragraphs. Split a beat that contains multiple moves or needs several subheadings.

## Pulling from the pile

Paraphrase, split, combine, or quote the raw material to fill each beat.

## Ending the journey

End when the journey is complete, even if fragments remain unused.

## Writing rhythm

- Append one selected beat at a time; never write ahead.
- Re-read the article before every write and preserve user edits. Substantial edits to earlier beats may change the next choices.
- Rewrite or replace specific beats when asked, leaving the rest alone.

</supporting-info>
