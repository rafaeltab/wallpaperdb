# Verify main rebases and review reconstructed heads

[Issue #759](https://github.com/rafaeltab/wallpaperdb/issues/759) permits agents to incorporate authenticated newer main history within the factory-selected base policy. The agent reports its actual comparison in the shared [versioned state response](../../src/capabilities/job/contract.ts). The factory verifies remote main ancestry, the retained original boundary and issue-only suffix before carrying that comparison into immutable successor stages. Reporting a SHA cannot authorize a different feature base, dropped unmerged prerequisites or an agent-created stack. Missing issue code follows the existing dependency handback workflow.

The [join adapter](../../src/adapters/github/joins.ts) normalizes authenticated main-rooted layers using Git first and preserves the selected prerequisite order. Uncovered feature parents prevent normalization. Issue-only replay, verified landing containment, retained worktrees, expected-head leases and independent metadata reconciliation continue to protect reconstruction and publication.

Changed heads require fresh local validation and independent Standards, Spec and Defects review. This supersedes the review carryover trade-off in [ADR 0003](0003-linearize-verified-unmerged-prerequisites.md), including simple conflict resolutions. Original review provenance remains separate from review of the reconstructed head. Automatic replay review and conflict fallback use retained operation identities and the shared state contract; an exact restack target, complete descendant inactivity and clean current HEAD gate acceptance. Publication and hosted CI remain separate gates, with dependents withheld until all are verified.

Advancement of main without a changed issue head or target does not invalidate successful CI or require another review. Unexpected bases, uncertain outcomes and stale observations remain retained recovery states. This decision authorizes no live deployment or production-state repair. See [recovery operations](../../OPERATIONS.md#rebase-comparisons).
