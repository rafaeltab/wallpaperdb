title: User Service
description: User management service for tracking sign-ups and profiles
---

The User Service owns WallpaperDB's public Profiles. It verifies Clerk-authenticated Users, persists authoritative Profile state and Handle claims in PostgreSQL, and records typed Profile events for downstream consumers.

**Status:** 🚧 In Development

## Quick Start

```bash
# Start infrastructure
make infra-start

# Run user service in development mode
make user-dev

# The service starts on http://localhost:3009
```

## Features

### Core Functionality
- **Authenticated Profile creation** through an idempotent ensure command
- **Optimistic Profile editing** with authoritative command responses and conflict detection
- **Unique Handle allocation** with normalization, reserved-name protection, collision retries, and monotonic claim generations
- **Transactional Profile events** recorded in an outbox with the authoritative Profile snapshot
- **Health checks** for database and message queue connectivity

### Observability
- **OpenTelemetry** traces and metrics
- **Structured logging** with Pino
- **Health checks** for all dependencies

## Architecture

### Event Flow

```
Web + Clerk JWT → User Service → PostgreSQL (Profile + Handle claim)
                                      ↓ same transaction
                                Profile event outbox
```

### Database Schema

```typescript
profiles {
  id: text                    // Clerk user ID and primary key
  displayName: text
  handle: text                // Case-insensitively unique
  biographyMarkdown: text
  pictureAssetId: text | null
  version: integer
  createdAt: timestamp
  updatedAt: timestamp
}

handleClaims {
  handle: text                // Case-insensitively unique claim
  profileId: text
  kind: text
  claimGeneration: bigserial // Monotonic projection conflict tiebreaker
  createdAt: timestamp
}
```

## API Reference

### POST /profile/me/ensure

Verifies the Clerk bearer token and idempotently creates or returns the signed-in User's authoritative Profile. A failed Clerk identity lookup returns `503 Service Unavailable` and persists nothing.

### PATCH /profile/me

Updates the signed-in User's Display name. The request supplies `displayName` and the last-seen `expectedVersion`. Display names preserve casing and Unicode while trimming and collapsing whitespace, and default to an 80-Unicode-character limit. Stale versions return `409 Conflict` without changing Profile state or recording an event. A successful command returns the authoritative updated Profile immediately and records a versioned `profile.updated` event in the same transaction.

### GET /health

Health check with dependency status.

**Response (200):**
```json
{
  "status": "healthy",
  "checks": {
    "database": { "status": "healthy" },
    "nats": { "status": "healthy" },
    "otel": { "status": "healthy" }
  }
}
```

### GET /ready

Kubernetes-style readiness probe.

**Response (200):**
```json
{
  "ready": true
}
```

## Configuration

Environment variables (Zod-validated):

```bash
# Server
PORT=3009
NODE_ENV=development

# Database
DATABASE_URL=postgresql://wallpaperdb:wallpaperdb@localhost:5432/wallpaperdb_user

# NATS
NATS_URL=nats://localhost:4222
NATS_STREAM=WALLPAPER

# OpenTelemetry
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
OTEL_SERVICE_NAME=user

# Clerk
CLERK_SECRET_KEY=sk_test_...
CLERK_PUBLISHABLE_KEY=pk_test_...

# Profile Handles
PROFILE_HANDLE_MIN_LENGTH=1
PROFILE_HANDLE_MAX_LENGTH=30
PROFILE_DISPLAY_NAME_MAX_LENGTH=80
```
