---
name: do-work
description: Implement one issue in the supplied checkout, review it, and publish a PR.
---

Use the existing checkout. If given a predecessor PR, stack your PR on it.

1. Use [$implement](../../engineering/implement/SKILL.md) for implementation and validation. Pass the issue URL, comparison base or predecessor PR, and retained user decisions. Continue only after its implementation obligations are complete. Retain its requirements/scope record, tested commit, validation, and demonstration for the following steps.
2. **Review and fix.** Run separate read-only subagents in parallel, one using $code-review and one using $review-agent, against the same complete issue change. Pass the recorded originating requirements as the spec source. For production behavior, tests, or helpers, gather the surrounding implementation and owning suites under [code review](../../engineering/code-review/SKILL.md) and assess test meaning as well as execution. Compare against the predecessor PR when supplied, otherwise the default base. Include the [task-scope context](../../../../docs/agents/task-scope.md) in both briefs and every repeated round. Record comparisons and results under the shared [review evidence policy](../../../../CONTRIBUTING.md#review-evidence). Verify findings under task scope, fix confirmed in-scope issues with new commits, and repeat required validation and affected reviews until no required findings or scope decisions remain pending. Handle independent base advances with unchanged PR head and base branch under the [PR history policy](../../../../CONTRIBUTING.md#pull-request-history). For reviewed-work or base-branch changes, assess prior evidence before dispatching another round; carry forward applicable evidence and review material or unresolved changes with their interactions. Report user-deferred proposals separately. Unavailable or failed required reviewers leave this step incomplete.
3. Use [$publish-pr](../publish-pr/SKILL.md) with the implementation handoff and applicable independent review evidence. Complete its publication obligations before reporting the manual workflow complete.

Run these steps in order in this checkout. The stage skills do not call this wrapper or each other. Their completion markers describe only their own stages; implementation completion alone does not complete `do-work`. This wrapper retains review coordination until the separate review-loop workflow is available.
